Case Study:
Monster Hunter Wilds

What design choices did you make and why?

One of the biggest design choices I made was using a dark color palette inspired directly by Monster Hunter Wilds. I used dark charcoal and brown backgrounds with cream, orange, and green accents to match the atmosphere and visual style of the game. I also chose Playfair Display SC for my headings to give the website a more fantasy-inspired, adventurous feel. For the body text, I used Commissioner because it is easier to read and works well for a website with a lot of information. I wanted the website to feel like it belonged in the world of Monster Hunter while still being organized and easy for new players to navigate.

Between my original Figma design and the finished website, I had to make some adjustments when translating the design into HTML and CSS. I focused on making sure the images, text, navigation, and spacing worked together properly on the actual webpage. I also made sure the different sections were clearly separated so users could easily find information about the game. The goal was to keep the original visual direction while making the finished version functional.

What was difficult to code? How did you solve it?

One of the more difficult parts of coding was getting the layout and positioning of the different elements to work correctly. I had to make sure the sidebar navigation stayed organized alongside the main content without interfering with the reading experience. Another challenge was placing and sizing the images throughout the page so they fit naturally within each section without stretching or disrupting the layout.

I solved these problems by adjusting my CSS and testing different layout properties until everything lined up correctly. I used the browser inspector to check element sizes, margins, padding, and positioning. This helped me understand which elements were causing spacing issues and allowed me to make adjustments without changing the entire layout. Breaking the page into individual sections also made it easier to manage the styling.

How did you adapt your design for mobile?

For mobile, I adapted the layout so the website would be easier to navigate on smaller screens. At 640px and narrower, the layout changes from a sidebar and main content arrangement into a single-column layout. The navigation moves above the content so users can access the different sections more easily. I also adjusted the images and spacing to fit smaller screens, hid the decorative placed images where necessary, and stacked the footer buttons vertically instead of keeping them side by side.

I tested the website at 1440px, 700px, and 375px to see how it behaved at different screen sizes. At 1440px, I checked the overall desktop layout and spacing. At 700px, I checked how the sidebar and content adjusted as the screen became narrower. At 375px, I focused on making sure the text, images, and navigation fit without creating horizontal scrolling or overlapping elements. These tests helped me make the website more consistent across different devices.

What did you learn about Flexbox or CSS positioning?

I learned that Flexbox makes it much easier to organize elements and control how they are arranged on a webpage. Instead of manually positioning everything, I could use properties like display: flex, flex-direction, align-items, and justify-content to control the layout. I also learned that align-self: flex-start is useful for keeping the sidebar aligned at the top rather than having it stretch to match the height of the main content. Understanding how these properties work together made building the overall page layout much easier.

I also learned how important CSS positioning is when working with decorative elements and images. Using position: relative on a section allows elements inside it with position: absolute to be positioned in relation to that section. This is useful when placing decorative images or backgrounds without affecting the normal flow of the content. I learned that positioning requires careful testing because an element can easily overlap other content or appear in the wrong location if its parent container is not set up correctly.

What would you add or change with more time?

With more time, I would add more interactive features to the field guide. For example, I would like to include clickable monster profiles, expandable information panels, and more detailed explanations of weapons and game mechanics. Since the website is designed for brand-new players, I think interactive guides and additional visual references would make it easier for people to understand the game without feeling overwhelmed.

I would also spend more time refining the overall layout and typography, especially the readability of the smaller body text. Some of the information sections contain a lot of content, so I would experiment with additional spacing, clearer visual hierarchy, and more organized content blocks. I would also like to improve the mobile experience further. Overall, I would keep the same Monster Hunter-inspired visual identity but make the website even easier to navigate and use.
